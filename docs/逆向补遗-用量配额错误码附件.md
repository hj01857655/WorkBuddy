## 一、用量与配额端点族

### 1. 个人版用量（`getPersonalUsage`，asar @138119796；**实测通过 2026-09-26**）

官方 `httpService` 的 baseURL 已含 `/v2`，故调用路径**不带 `/v2`**：

```http
POST {endpoint}/v2/billing/meter/get-user-resource-summary      ← 资源汇总（实测 cn 域 200/code=0）
POST {endpoint}/v2/billing/meter/get-user-resource-paid-packages ← 付费资源包（分页，NeedRenewInfo: true）⬜
POST {endpoint}/v2/billing/meter/get-user-resource-free-packages ← 免费资源包（分页，带切片周期区间）⬜
```

实测 summary 响应：`data.Packages[] = {PackageCode, CycleTotalCapacity,
CycleRemainCapacity, CycleUsedCapacity, CapacityUnit: "credits", TotalCount}`，
另有 `IsPaidUser`、`SubscriptionPackageCode`。

头 = `buildHeaders(session)`（同签到基础头，**不含** Turing 头）+ `Accept-Language`（按 locale）。
`fetchUserResources` 并发拉三路，返回 `{resources, summary, failedSources}`。

### 2. 企业版用量（`getEnterpriseUsage`，asar @138116939）

```http
POST {endpoint}/v2/billing/meter/get-enterprise-user-usage
<buildHeaders>
body: {}
```

响应取 `data.data || data || 根`，判据 `typeof usageData.limitNum === "number"`；
字段含 `credit`、`cycleResetTime`；**`limitNum === -1` 表示不限量**（官方有
`UNLIMITED_USAGE_SENTINEL` 哨兵）。返回 `{usageLeft, usageTotal, editionType, refreshAt}`。

### 3. 项目配额（`/console/as/teams/me/quota`，asar @135238533，⬜ 未实测）

```http
GET /console/as/teams/me/quota
→ { data: { plan, limits: { maxOwnedProjects, maxProjectMembers }, usage: { ownedProjects } } }
```

错误语义：HTTP 403 或业务码 **17261** = `ExclusivePlanNotSupportedError`（专属版不支持）。
注意：这是**项目数配额**，不是 credit 用量；`/authz/v1/accounts/check_limit` 属
OneID 登录组件，与聊天用量无关，勿混淆。

## 二、错误码表（bridge 错误归一用）

| 业务码 | 含义 | 出处 |
|---|---|---|
| `0` | 成功 | 全站信封 |
| `10001` | **今天已签到**（HTTP 400，签到幂等成功场景，实测 2026-09-26） | daily-checkin 实测 |
| `11217` | **auth/token 轮询 pending**（浏览器还没登录完） | `isLoginPollPending(envelope, 11217)`，4 处（@115923068 等） |
| `12151` | **login/account 轮询 pending** | `isLoginPollPending(envelope, 12151)`，4 处（@115924632 等） |
| `10081` | `RESPONSE_CODE_IP_LIMIT`，IP 限频 → 网关应映射 429 | asar `RESPONSE_CODE_IP_LIMIT = 10081`（@138093 区域附近） |
| `17261` | `ExclusivePlanNotSupportedError`，专属版不支持项目配额 | quota 路由注释（@135238985） |
| `400` + msg 含「已签到/already/checkin」 | 已签到（幂等成功） | 《认证与签到协议.md》第五节 |

**轮询信封读取**（`readLoginEnvelopeCode`，@115905597）：取
`response?.data?.code ?? response?.code`，是 number 才算数。
**account 轮询的 HTTP 401/403**：官方按 `MAX_ACCOUNT_AUTH_RETRIES` 重试（@115924928）——
网关 401 自愈可参考同语义。

> 其余业务码未枚举：asar 里数字常量与 asar 索引哈希混淆严重，置信度高的就上表五个。
> 遇到新码时以「HTTP 状态 + msg 关键词」兜底，勿硬编码猜测值。

## 三、多模态附件链路（`wb.http.upload`，asar @130084150，⬜ 未实测）

官方四步（`uploadCore`）：

1. 生成 objectKey：`uploads/{timestamp}-{random}-{sanitizedFilename}`
2. `POST /console/as/support/presigned_url`，body `{"object_keys": ["<objectKey>"]}`
   → `data.items[0]` 含 `upload_url` 与 `download_url`
3. `PUT {upload_url}`（腾讯云 COS），body = 文件 Blob，头 `Content-Type: <mimeType>`；非 2xx 抛
   `COS PUT failed: <status>`
4. 返回 `{url: download_url, size, mimeType}` —— 后续消息里引用 `download_url`

另一条读取路径（`artifacts.locate`，@116860702）：`agent://files/<objectKey>` URI
→ 同一 `presigned_url` 端点换 `download_url`。

**对网关的含义**：要支持带图/带文件聊天，需先实现 presigned_url + COS PUT 代理，
再把 `download_url` 塞进消息体；`/v1/attachments` 命中项是飞书 SDK，与 WorkBuddy 无关。

## 四、图灵盾设备 token（签到依赖，详见协议文档第五节）

`X-Device-Token` / `X-Device-Token-Error` 互斥头，token 由腾讯图灵盾 SDK 主进程后台原生
采集（`qm/qm-helper.exe`、`qimei.dll` 为其本机组件），best-effort、非硬前置。
网关若复刻：无 SDK 环境下可先不带该头实测签到（官方 provider 缺失时同样不发）。
