# WorkBuddy 网关协议清单

基准：WorkBuddy 5.6.2 · CN 账号 · `copilot.tencent.com` · 2026-09-26 实测。

---

## 一、官方用 SDK 还是手搓

**两条路并存，按用途分：**

| 用途 | 实现 | 代码证据 |
| --- | --- | --- |
| **主 agent 调模型** | **OpenAI 官方 Node SDK**（stainless 生成） | `createClient()` → `new OpenAI(this.buildOpenAIClientOptions(...))`；`buildOpenAIClientOptions()` 返回 `{baseURL, apiKey, fetch: this.axiosToFetchAdapter(), maxRetries: 0, timeout}` |
| **Computer-Use VLM 透传** | **手搓 raw `fetch`** | `vlm-upstream.ts` 注释：*「请求体与响应体按字节转发，不解析不改写」*；`fetchImpl(resolveUpstreamUrl(), {method:"POST", headers, body})` |

即：**业务调用走 SDK，字节透传走手搓。** SDK 的 `baseURL` = 产品端点（网关），`apiKey` = 当前登录态令牌。

SDK 里同时准备了 `chat.completions.*` 与 `responses.*` 两套资源对象 —— 但**SDK 里有 ≠ 网关实现了**，实测见第二节。

## 二、协议可用性总表（实测）

| 路径 | 状态 | 证据 |
| --- | --- | --- |
| `/v2/chat/completions` | ✅ **主力，可用** | `200` + `text/event-stream` |
| **`/v2/enterprises/{personal\|<eid>}/models`** | ✅ **可用** | `200`，26.6 KB，含 **30 个模型 + 13 个 agent** + 产品配置 |
| `/v2/embeddings` | ✅ **可用** | `200`，`bge-m3` 返回真实向量（1024 维） |
| `/responses`（**无 `/v2`**） | ⚠️ 路由存在，当前不可用 | 空 body → `400 invalid_request_error`（真在做模型解析）；带 model → `502 upstream_error` |
| `/v2/completions`（legacy） | ⚠️ 路由存在 | 无 stream → `400/11101`；`glm-5.3` → `500/11102 Invalid model`（非 completion 类模型） |
| `/v2/images/generations` | ⚠️ 路由存在，模型名未知 | 空 body → `400/14401` `Image model [] route config not found` |

**不存在的路径（实测 `404`）**：`/v2/messages`、`/messages`、`/v2/responses`、`/v1/chat/completions`。

即：**chat 是主力，`models`（模型目录）与 `embeddings` 也可用；
`responses` / `completions` / `images` 有路由但当前不可用；
Anthropic Messages 协议未实现；OpenAI 标准前缀 `/v1` 不暴露。**

## 三、`/v2/enterprises/{id}/models`（模型目录，可用）

```
GET https://copilot.tencent.com/v2/enterprises/personal/models
Authorization: Bearer <accessToken>
```

别名 `GET /console/enterprises/personal/models` 返回内容一致。
路径中的 `{id}` 个人账号填 `personal`，企业账号填 `enterpriseId`。

**响应 `data` 结构**：

| 键 | 内容 |
| --- | --- |
| `models` | **模型目录，实测 30 项**（每项含 `id`/`name`/`vendor`/`maxInputTokens`/`maxOutputTokens`/`supportsToolCall`/`supportsImages`/`supportsReasoning`/`reasoning`/`temperature`/`tags` 等） |
| `agents` | **13 项**，各带自己的 `models` 子集、`tools`、`commands`、`instructions` |
| `endpoint` | `https://copilot.tencent.com` |
| `stagingEndpoint` | `https://staging-copilot.tencent.com` |
| `links` | 官网、帮助文档、MCP/hooks/sandbox 文档、issue 链接 |
| `mergeStrategy` | `"merge"` |
| `productFeatures` | 9 个 boolean 开关 |

**实测 `cli` agent 可用模型（16 个）**：

```
auto  hy4-preview  hy3  hy3-x  deepseek-v4.1-flash  glm-5.3  glm-5.3-flash
glm-5.2  glm-5.1  glm-5v-turbo  kimi-k3-1  kimi-k2.8-preview  kimi-k2.7
kimi-k2.6  minimax-m3  deepseek-v4-pro
```

**三个 id 细节（实测）**：`kimi-k3` 是 `kimi-k3-1` 的别名（都能 200）；
`default` 映射到 `glm-5.3`；`gpt-5.6-sol` 等返回 `11102 is only available for authorized users`（存在但需授权）。

完整模型表见 **《聊天接口规格.md》第八节**。

## 四、`/v2/chat/completions`（主力，可用）

```
POST https://copilot.tencent.com/v2/chat/completions
Authorization: Bearer <accessToken>
Content-Type: application/json
```

### 请求

```json
{
  "model": "glm-5.3",
  "stream": true,
  "messages": [{ "role": "user", "content": "说个你好" }]
}
```

必填：`model`（string）、`messages`（非空数组）、`stream`（**必须 `true`**）。

可选——**按效力分三档**（2026-10-10 行为复核，见《聊天接口规格》§5.2.1 与 24 号审计）：

| 档 | 字段 |
| --- | --- |
| 真生效 | `max_tokens`（但按后端分裂）、`tools`、`temperature`、`reasoning_effort`、`tool_choice`（仅字符串，且支持面按后端不同） |
| 在结构体但不执行 / 效力未定 | `stop`（实测不截断）、`top_p`（实测不收敛）、`n`（恒 1 choice）、`presence_penalty`/`frequency_penalty`（仅负向看到差异）、`user`（不可观测）、`logit_bias`、`prediction` |
| 不在结构体（等于不支持） | `seed`、`top_k`、`logprobs`/`top_logprobs`、`response_format`、`max_completion_tokens`、`parallel_tool_calls`、`modalities`、`audio`、`store`、`metadata`、`safety_identifier`、`web_search_options`、`agent` |

另：`stream_options.include_usage` 可发，但上游**默认就带 usage**（见下）。
上游只收结构体里的键：结构体外的键被静默丢弃、非法取值一律默许，**只有类型不符才 `400/11101`**，
所以拿 200 当“支持”证据会错。

### 响应（SSE）

```
Content-Type: text/event-stream
Cache-Control: no-cache
Transfer-Encoding: chunked
```

帧序：

```
: heartbeat
data: {"id":"…","object":"chat.completion.chunk","model":"glm-5.3","created":1790358436,
       "choices":[{"index":0,"delta":{…},"logprobs":null,"finish_reason":""}],"usage":null}

data: {… "delta":{"content":"4"} …}

data: {… "finish_reason":"stop", "usage":{…}}      ← 收尾帧，usage 内联在此
data: [DONE]
```

chunk 结构：

```ts
{
  id: string
  object: "chat.completion.chunk"
  model: string
  created: number                                   // Unix 秒
  choices: [{
    index: number
    delta: {
      role: "assistant"
      content: string                               // 正文增量
      reasoning_content: string                     // 思维链增量（本接口特有）
      function_call: null | {name,arguments}        // 恒无信息量
      refusal: string
      tool_calls: [] | [{index,id?,type?,function?}]// 按 index 合并
      extra_fields: null
    }
    logprobs: null
    finish_reason: "" | "stop" | "length" | "tool_calls"
  }]
  usage: null | {
    prompt_tokens; completion_tokens; total_tokens
    completion_tokens_details: { reasoning_tokens; cached_tokens; … }
    prompt_tokens_details: { … }
    prompt_cache_hit_tokens; prompt_cache_miss_tokens
    cache_read_input_tokens; cache_creation_input_tokens; prompt_cache_write_tokens
    completion_thinking_tokens
    credit                                        // 本次消耗积分
    cached_tokens
  }
}
```

**四条结构规则**：

1. 进行中 `finish_reason` 是 **`""`**，不是 `null`。
2. `usage` 只出现在收尾帧，且该帧 `choices` **非空**。
3. `delta` **每帧 7 键齐全**（空值为 `""`/`[]`/`null`）—— 判空判值，不判键。
4. `tool_calls` 按 **`index`** 合并；`id`/`type`/`function.name` **只在首帧**；`function.arguments` 是流式 JSON 片段，**拼接后**再解析。

详细版（含逐帧原文、9 个坑、实测记录）见 **《聊天接口规格.md》**。

## 四、`/responses`（路由存在，当前不可用）

```
POST https://copilot.tencent.com/responses          ← 注意：没有 /v2
Authorization: Bearer <accessToken>
Content-Type: application/json
```

**实测**：带 `model` 的请求一律 **`502`**：

```json
{"error":{"code":"upstream_error","message":"invoke model error","type":"upstream_error"}}
```

（空 body 则报 `400` `model [] service info not found` —— 说明路由与 `model` 解析已实现，
只是卡在上游调用。`glm-5.3` / `kimi-k3` / `auto`、`input` 为 string 或数组、`stream: true`——
各种形态全部同此 `502`。）

**结论：不可用。** SSE 未观测到，不推测其帧格式。
错误信封是 **OpenAI 风格嵌套**（见第八节 B）。

## 五、`/v2/completions`（legacy，路由存在）

```
POST https://copilot.tencent.com/v2/completions
```

| 请求 | 响应 |
| --- | --- |
| `{"model":"glm-5.3","prompt":"say hi"}`（无 stream） | `400` `{"code":11101,"msg":"Non-stream completion request is currently not supported"}` |
| `{"model":"glm-5.3","prompt":"say hi","stream":true}` | `500` `{"code":11102,"msg":"Stream completion failed with error: Invalid model [glm-5.3]"}` |

**结论**：路由存在、**同样强制流式**，但 `glm-5.3` 不是 completion 类模型。
**未找到可用的 completion 模型名**，故 SSE 帧格式未观测。

## 六、`/v2/embeddings`（**可用**）

```
POST https://copilot.tencent.com/v2/embeddings
Authorization: Bearer <accessToken>
Content-Type: application/json
```

### 请求

```json
{ "model": "bge-m3", "input": "测试文本" }
```

`input` 支持字符串与字符串数组（均实测 200）。

### 响应

```json
{
  "data": [
    { "embedding": [-0.004205198, 0.017313642, …], "index": 0, "object": "embedding" },
    { "embedding": [ … ], "index": 1, "object": "embedding" }
  ],
  "model": "bge-m3",
  "object": "list",
  "usage": { "prompt_tokens": 8, "total_tokens": 8 }
}
```

- 向量维度 **1024**（`bge-m3`）
- **完全 OpenAI 兼容**的 embedding 结构（`data[].embedding` / `object: "list"` / `usage`）
- **非 SSE**，单次 JSON 响应

### 模型名

| 模型 | 结果 |
| --- | --- |
| **`bge-m3`** | ✅ `200`，返回向量 |
| `bge-large-zh`、`text-embedding-3-small`、`text-embedding-v3`、`glm-embedding`、`embedding-3` | ❌ `500` `{"code":11351,"msg":"Generate embedding failed with error: 11351:embedding model [X] not found"}` |

## 七、`/v2/images/generations`（路由存在，模型名未知）

| 请求 | 响应 |
| --- | --- |
| `{}` 或 `{"prompt":"a cat"}` | `400` `{"code":14401,"msg":"Create image failed with error: Image model [] route config not found"}` |

## 八、错误信封（两套结构）

网关有**两套互不兼容**的错误结构，必须按路径区分：

**A. chat / embeddings / completions / images 族** —— 扁平码：

```json
{
  "code": 11101,
  "msg": "…",
  "requestId": "…",
  "extError": { "code": "400002", "message": "…", "param": "messages",
                "type": "invalid_request_error", "StatusCode": 400 },
  "displayMsg":  { "en": "…", "zh": "…", "zh-hant": "…" },
  "displayTips": { "en": "…", "zh": "…", "zh-hant": "…" },
  "actions": ["RETRY", "SUBMIT_FEEDBACK", "SWITCH_MODEL", "NEW_CONVERSATION"]
}
```

> `extError.param` 是**出错字段名**（上面示例是请求体里的 `messages` 数组），不是路径。

**B. `/responses` 族** —— OpenAI 风格嵌套：

```json
{ "error": { "code": "invalid_request_error", "message": "…", "type": "invalid_request_error" } }
```

**`code` 是通用码，语义看 `msg`。** 示例：`11101` 一码两义 ——
未传 `stream` 时是 `Non-stream chat request is currently not supported`，
字段类型错时是 `Unmarshal chat params failed with error: …`。
同理 `11102` 既用于 `model [X] service info not found`，也用于 `Invalid model [X]`。
**禁止按 `code` 判分支。**

另有 `401`（缺令牌）：响应是 **HTML**（`Server: APISIX`），**无 JSON 信封**，须先看 `Content-Type`。

## 九、端点与基址

| 项 | 值 |
| --- | --- |
| CN 网关 | `https://copilot.tencent.com` |
| CN（`{domain}` 亦可） | `https://www.workbuddy.cn` |
| 前缀 | chat/completions/embeddings/images = **`/v2/`**；**`/responses` 不带 `/v2`** |
| 鉴权 | `Authorization: Bearer <accessToken>`（**唯一必需头**，实测仅带它 + `Content-Type` 即可 200） |
| 无令牌 | `401`（HTML，APISIX） |

必需头仅 `Authorization` + `Content-Type`。其余头（`X-User-Id`/`X-Domain`/`X-Product`/
`X-IDE-*`/`X-Conversation-*`/trace 三件套）**不带头不会失败**，作用是会话归属、链路追踪与产品统计。
